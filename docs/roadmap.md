# SchemaGuard — Roadmap

Oct 7, 2026. About 5 weeks of solo, part-time work, assuming about 20 hours per week (to confirm). Every phase ends with something that runs.

See `docs/architecture.md` for the design and tech stack.

## How we work

Gazi writes the code; Claude acts as guide and mentor. For each step:

1. Claude explains the step: its purpose, the concepts, what to read.
2. Gazi builds it.
3. Claude reviews the code: points out bugs and why, asks questions instead of rewriting.
4. Check the step's "done when", then move on.

- [x] **2.3 Column usage.** For models that read a source directly, parse `compiled_code` with sqlglot to list the source columns they use. `SELECT *` means all columns, marked uncertain.

A `*` in a CTE narrowed by the outer query stays certain. Names match exactly. Real manifest: all 6 staging models give their real columns, `uncertain=False`. `tests/test_columns.py` has 15 tests (3 basic, 12 parametrized star/bad-SQL/UNION rows); 108 tests in total. ## Why this order

- Phases 1 and 2 are independent, so each can be learned and tested alone before the hard part (Phase 3).
- GitHub comes last: the whole tool works offline first, so CI and logic are never debugged at the same time.
- The scenario suite grows from Phase 1 onward, not at the end.
